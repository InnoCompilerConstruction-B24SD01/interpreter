# Project D

`dinterpret` выполняет программы на учебном динамически типизированном языке D
из курса Compiler Construction. Интерпретатор написан на C++17. На вход он
получает файл `.d`, а команды `print` записывают результат в стандартный поток
вывода.

## Как собрать и запустить на macOS

Нужны Python 3 и компилятор C++17: `g++` или `clang++`, доступный через `PATH`.
На macOS компилятор входит в Command Line Tools.

### 1. Перейдите в корень проекта

Корень проекта — каталог, в котором лежит `verify.py`. Если репозиторий находится
в `mage_arena/interpreter`, из каталога `mage_arena` выполните:

```sh
cd interpreter
```

Внутри репозитория тоже есть каталог `interpreter` — это модуль исполнителя.
Если вы находитесь в нём, поднимитесь на один уровень:

```sh
cd ..
```

Это два способа попасть в корень из разных каталогов. Выберите подходящий.
Проверьте содержимое текущего каталога:

```sh
ls -a
```

Здесь должны быть `verify.py`, `README.md`, `lexer`, `syntax`, `semantic`
и `interpreter`. После сборки появится скрытый каталог `.build`, который
виден благодаря флагу `-a`.

### 2. Соберите интерпретатор и проверьте примеры

```sh
python3 verify.py
```

При успешной сборке и проверке вывод на macOS такой:

```text
Built .build/darwin/dinterpret
Passed 11 examples with and without optimization.
```

Скрипт проверяет 11 программ в двух режимах: с оптимизацией и без неё.
Он сравнивает код завершения, стандартный вывод (`stdout`) и поток ошибок
(`stderr`) с ожидаемыми результатами. Шесть программ намеренно вызывают ошибки выполнения:
их проверка успешна, если сообщение и код завершения совпали с ожидаемыми.

Если нужна только сборка, используйте `python3 verify.py --build-only`.

### 3. Запустите отдельную программу

Из того же каталога выполните:

```sh
.build/darwin/dinterpret interpreter/examples/01_sum_discount.d
```

Программа складывает три цены и применяет скидку:

```text
before discount 60
after discount 50
```

Код завершения — `0`. Чтобы выполнить другой пример, замените имя файла после
`interpreter/examples/`.

### 4. Запустите с оптимизацией

```sh
.build/darwin/dinterpret --optimize interpreter/examples/03_factorial.d
```

Вывод:

```text
120
```

Программа рекурсивно считает факториал `5`. С оптимизацией и без неё
получается одинаковый результат.

## Запуск на других системах и своего файла

Скрипт сборки печатает путь к исполняемому файлу. На другой системе замените
путь в командах выше:

| Система | Исполняемый файл |
| --- | --- |
| macOS | `.build/darwin/dinterpret` |
| Linux | `.build/linux/dinterpret` |
| Windows | `.build/windows/dinterpret.exe` |

На Windows Python также можно запустить командой `py -3` вместо `python3`.
Синтаксис запуска своего файла:

```text
dinterpret [--optimize] file.d
```

Программа принимает один файл. Флаг `--optimize` ставится перед его путём.
Оптимизатор сворачивает поддерживаемые операции над константами и удаляет
команды после прямого `return` или `exit` в блоке. Перед преобразованием он
проверяет семантику всей программы; после преобразования дерево анализируется
заново и передаётся исполнителю.

## Одиннадцать примеров для защиты

В [каталоге примеров](interpreter/examples/README.md) приведены исходники,
команды, точный вывод и короткие пояснения для защиты. В каждом файле 3–9 строк
и одна основная идея. Все программы проходят предварительный анализ;
примеры 06–11 останавливаются именно во время исполнения.

| № | Что показать | Результат |
| --- | --- | --- |
| [01](interpreter/examples/01_sum_discount.d) | Сумма в цикле `for` и условие скидки | `60` до скидки, `50` после |
| [02](interpreter/examples/02_counter_closure.d) | Замыкание сохраняет изменяемую переменную | Последовательные вызовы дают `11` и `12` |
| [03](interpreter/examples/03_factorial.d) | Рекурсия и возврат из функции | Факториал `5` равен `120` |
| [04](interpreter/examples/04_array_snapshot.d) | Массив меняется во время обхода снимка | Цикл печатает `10`, `20`; массив становится `[10, 99]` |
| [05](interpreter/examples/05_square_search.d) | `while` повторно проверяет условие | Первое положительное число с квадратом больше `20` — `5` |
| [06](interpreter/examples/06_missing_index.d) | Чтение отсутствующего элемента массива | Ошибка ключа `3` |
| [07](interpreter/examples/07_invalid_operand.d) | Умножение числа на строку | Ошибка типов операндов |
| [08](interpreter/examples/08_missing_field.d) | Чтение отсутствующего поля кортежа | Ошибка поля `z` |
| [09](interpreter/examples/09_division_by_zero.d) | Деление на ноль внутри функции | Первый вызов печатает `10`, второй падает |
| [10](interpreter/examples/10_argument_count.d) | Передан один аргумент вместо двух | Первый вызов печатает `5`, второй падает |
| [11](interpreter/examples/11_recursion_limit.d) | Граница глубины рекурсии | 67 активных вызовов допустимы, 68-й отклоняется |

Для каждого примера каталог объясняет, почему получается такой результат
и какую функцию исполнителя показать в коде.

## Пример неуспешного запуска

```sh
.build/darwin/dinterpret interpreter/examples/09_division_by_zero.d
```

В `stdout` останутся результаты, выведенные до ошибки:

```text
10
```

В `stderr` появится сообщение:

```text
interpreter/examples/09_division_by_zero.d: runtime error at 1:44: division by zero
```

Второй вызов передаёт `count = 0`. Ошибка возникает внутри функции в первой
строке файла, где записано деление. Результат первого вызова уже напечатан
и сохраняется. Перед делением нужно проверить количество значений.

Для ошибок исходного кода диагностика содержит путь, строку и столбец.
Лексические, синтаксические и семантические ошибки обнаруживаются до исполнения
первой команды. Ошибка выполнения может возникнуть после уже сделанного вывода.

| Код завершения | Значение |
| --- | --- |
| `0` | Выполнение завершилось успешно |
| `1` | Ошибка чтения файла, анализа, выполнения или записи вывода |
| `2` | Неверные аргументы командной строки |

## Полная проверка

Из корня репозитория:

```sh
python3 verify.py --all
```

Этот режим дополнительно запускает исходные тесты лексера, парсера,
семантического анализатора, оптимизатора и 15 программ курса. Учебные материалы
курса хранятся отдельно от одиннадцати демонстрационных программ исполнителя.
На Windows для `--all` используйте WSL. Параметр `-v` показывает команды сборки
и подробный вывод проверок.

## Устройство проекта

```text
исходный текст → лексер → токены → парсер → AST
    → семантический анализ → дерево с привязками имён → исполнитель
```

Лексер выделяет элементы языка и сохраняет их позиции. Парсер строит дерево
конструкций. Семантический анализатор связывает имена с объявлениями и проверяет
допустимость конструкций. Исполнитель обходит дерево, вычисляет выражения,
меняет значения переменных и выполняет команды `print`.

| Каталог или файл | Назначение |
| --- | --- |
| `lexer/` | Лексер |
| `syntax/` | Парсер и AST |
| `semantic/` | Семантический анализ и оптимизация |
| `interpreter/` | Значения, окружения и исполнение дерева |
| `interpreter/src/main.cpp` | CLI и соединение этапов |
| `verify.py` | Сборка и проверка примеров |

Подробное описание исполнения: [README исполнителя](interpreter/README.md).
